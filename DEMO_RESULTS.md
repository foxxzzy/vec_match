# Vector Dating Backend Demo Results

Generated by `cargo run --bin demo_match`.

This demo uses synthetic users and the real local backend components. It reads prompt embeddings from the local database instead of hard-coding vectors into the demo. 

This is the output from the demo, you can rerun to verify it works but it will produce the same content as below, unless you chnage the content and the emebddings.

The interactions to the content are obivously extreme and done in a way to ensure match or no match, in reality the mathcing will not be as clean as displayed in the below results.

## Pipeline

1. Postgres hard gates check profile and preference compatibility.
2. Rejected pairs stop before personality scoring.
3. Passing pairs receive synthetic ledger interactions using stored prompt embeddings.
4. The existing vector code builds normalised personality vectors.
5. The existing weighted scorer calculates compatibility.
6. Selected pairs continue through queue decisions and final confirmation.

## Legend

| Term | Meaning |
| --- | --- |
| Hard gate | Database profile filter before vector scoring. |
| Axis score | Personality similarity from 0% to 100%. |
| Weight | Importance of that axis in the final score. |
| Weighted points | Axis score from 0 to 1 multiplied by its weight. |
| Active weight | Sum of weights for axis that had enough data to score. |
| Final score | Total weighted points divided by active weight. |
| Pass threshold | 60% |
